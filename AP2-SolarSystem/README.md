## 一、运行方式

### 本地运行

项目是纯静态页面，找一个静态服务器把根目录指向项目文件夹就能跑，比如：

```bash
cd AP2-SolarSystem
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000
```

要注意页面必须通过 http:// 打开，用 VS Code 的 Live Server 或者上面这条 python 命令都可以；如果直接双击 index.html 也就是以 file:// 方式打开，浏览器会禁止把图片纹理传给 WebGL，画面会一直停在灰色的小球上，这个坑调试时踩过一次。

### 公网访问

**在线演示地址：<https://xiaoxiayk.github.io/jsjtxap1/AP2-SolarSystem/>**，浏览器直接打开即可运行，无需任何安装。

部署过程：把仓库推到 GitHub 之后，打开仓库设置里的 Pages 页，把 Source 选成 main 分支的根目录再保存，等一分钟左右 GitHub 就会自动生成上面的访问地址；Gitee Pages 或者个人主页的做法也是类似的。

## 三、漫游说明，对应交付物里的 10 秒漫游录屏

页面首次加载默认就是漫游，也可以按 `T` 进入；相机沿着 6 个关键帧绕场景转一整圈，关键帧里存的是球坐标的方位角、仰角和距离三个数，帧与帧之间用周期 Catmull-Rom 插值衔接，一圈 36 秒，最后一帧会平滑接回第一帧；路线安排上先冲到内行星附近拉近，再拉远掠过外行星。漫游过程中按空格可以暂停和继续，拖动鼠标就切换成手动视角，按 `T` 又能回到漫游路径，两种模式来回切换没有次数限制。

10 秒漫游录屏在 [screenshots/tour-10s.webm](screenshots/tour-10s.webm) 这个文件里，是用浏览器里的 canvas.captureStream(30) 加 MediaRecorder 直接录出来的，格式为 WebM，帧率 30。

## 四、实现要点

### 1. 层级结构，模型矩阵一层层相乘

所有天体的参数，比如半径、轨道半径、周期和倾角，都集中写在 js/config.js 里；js/scene.js 每一帧从太阳开始自顶向下把模型矩阵一层层乘出来，做法相当于维护一个矩阵栈，相乘用的是 MV.js 提供的 mult：

```
太阳系（世界坐标系）
├── 太阳   M_sun = R_y(spin_sun) · S(r_sun)                          [自发光]
├── 行星 i                          （水金地火木土天海，E1 扩展）
│     M_orbit_i = R_y(θ_i) · T(d_i,0,0)                ← 公转（θ_i 由开普勒第三定律 ω=K/d^1.5 求出）
│     M_i = M_orbit_i · R_z(tilt_i) · R_y(spin_i) · S(r_i)     ← 倾角先转，自转再转
│           └── 土星环  M_ring = M_orbit_sat · R_z(26.7°) · R_x(90°) · S(r_sat)
└── 地球分支
      M_earth = M_orbit_e · R_z(23.5°) · R_y(spin_e) · S(r_e)
            ├── 地轴线  M_axis = M_orbit_e · R_z(23.5°)
            └── 月球（第四级）
                  M_moonOrbit = M_orbit_e · M_tilt_manual · R_y(θ_m) · T(d_m,0,0)
                  M_moon = M_moonOrbit · R_y(spin_m) · S(r_m)
```

地球 23.5 度轴倾角的实现顺序是必做 1 的核心。倾斜旋转 R_z(tilt) 作用在地球自己的模型矩阵上，也就是乘在内侧，公转的轨道矩阵 M_orbit 乘在外侧，先倾斜、后公转；如果反过来写成 R_z(tilt) · M_orbit，倾斜就会在平移之前被作用到原点上，公转半径和姿态都会被破坏掉，所以变换的顺序直接决定结构。按矩阵作用的先后顺序理解：顶点先被缩放，再绕倾斜后的自身轴自转，然后整体倾斜 23.5 度，最后被公转矩阵带到轨道上的位置，这样自转轴从头到尾都是倾斜着的。

### 2. 手动矩阵，月球轨道面的倾斜，必做 2，对应教材第 4 章的变换推导

月球的轨道面相对黄道面倾斜 5.14 度，倾斜轴是两个平面的交线，也就是节点线 n = (cos Ω, 0, sin Ω)，其中 Ω 是升交点经度，取 125 度。这里没有用 MV.js 封装好的 rotate(angle, axis)，绕任意轴旋转的复合函数是题目要求避开的，实现时把整个旋转手工拆成对齐、旋转、还原三步基本变换，再用 mult 一层层乘起来，代码在 js/scene.js 里：

```
M_tilt = R_y(-Ω) · R_x(i) · R_y(Ω)

  1) R_y(Ω)   ：把节点线 n 旋转到与 X 轴重合（因为 R_y(Ω)·n = (1,0,0)）
  2) R_x(i)   ：绕 X 轴把轨道面倾斜 i 角
  3) R_y(-Ω)  ：把节点线转回原方位（共轭还原）
```

它的原理就是共轭分解，绕任意轴 u 转 θ 角可以写成 A⁻¹ · R_axis · A；月球轨道线那个黄色圆环之所以是斜的，来源就是这个矩阵，在地月特写截图里能看到月球轨道面和行星轨道面不在同一个平面上。另外 Ω 并不是固定值，按 Ω(t) = 125° − 0.43°/s · t 缓慢减小，对应真实世界里升交点西退、18.6 年一个周期的现象，按场景时间做了缩放；有了这个西退，月球的轨道环会慢慢进动，日食和月食才会像真实世界那样成"食季"出现，不然地球 45 秒和月球 15 秒的周期接近 3 比 1，每次满月都会被锁在交点同一个相位上，血月基本就看不见了。

### 3. 表面纹理和 UNPACK_FLIP_Y_WEBGL，必做 3

太阳、地球、月球，加上全部 8 颗行星、土星环和星空球，都贴了位图纹理；流程是先用 Image 异步加载图片，再通过 gl.texImage2D 传给显卡，然后生成 mipmap 并采用三线性过滤，球面的 UV 坐标由 js/geometry.js 里的 createSphereData 参数化生成。

贴图一开始上下是颠倒的，原因在于图像文件的原点在左上角，行号向下增长，而纹理坐标 UV 的原点在左下角，v 是向上的；直接上传的话，图像的第一行也就是地图里的北极会落到 v=0 上，采样出来的地球南北半球就反了。解决办法是上传前加一行设置：

```js
gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, true);   // 上传时垂直翻转一行
```

再配合球面 UV 取 v = 1 - i/stacks，让北极对应 v=1，两个措施一起用，贴图的北方就朝上了；月球、火星等其他贴图也是同样处理，细节写在 js/main.js 的 loadTexture 函数注释里。

### 4. 双投影对比，必做 4，按 O 键切换

两张截图用的是同一个机位，先把漫游暂停再切换；为了让切换瞬间画面大小一致，正交投影的半高取 d·tan(fov/2)，与透视的视锥对齐：

| 透视投影 perspective | 正交投影 ortho |
|---|---|
| ![透视](screenshots/overview-perspective.png) | ![正交](screenshots/overview-orthographic.png) |

透视的效果是近大远小，内侧轨道的水星、金星看起来比远处的天王星、海王星大不少，轨道线因为透视收缩变成左右不对称的椭圆，靠近相机的一侧张角更大；正交的效果是不管物体远近画出来都一样大，行星的视觉大小只由半径决定，轨道线是规整等距的椭圆，没有汇聚，相当于从无限远处看过去的视图。两者对比，透视有纵深感，适合漫游，正交保留平行关系，适合比对大小；切换时最容易看出来的差别是外圈轨道有没有向后收缩，以及近处行星会不会突然变小。

### 5. 相机漫游与接管，必做 5

相机代码在 js/camera.js，是一个轨道相机，目标点固定在太阳上，位置用方位角、仰角和距离三个球坐标参数描述；漫游就是对这三个数做周期 Catmull-Rom 样条插值，每段 6 秒，插值保证二阶平滑，路径上不会出现折角；鼠标拖拽或者滚动滚轮会立刻切到手动模式，按 T 或者空格又能回到漫游，两种模式可以来回切换任意次。

### 6. 渲染与着色器

页面里写了三个着色器程序，源码放在 index.html 的 script 标签里，用教材的 initShaders 加载：

- tex 程序负责所有贴图天体，逐片元计算 Phong 光照，包含环境、漫反射和镜面三部分，对应教材第 6 章，点光源放在世界原点也就是太阳的位置；uEmissive 为 1 时跳过光照直接用纹理色，太阳和星空球走这条路；法线用 normalMatrix 变换，它由模型矩阵左上 3×3 求逆转置得到；
- flat 程序画轨道线和地轴线，用半透明混合，开着深度测试但关掉深度写入；
- belt 程序画小行星带，1500 个 gl.POINTS，每个点把圆轨道的半径、初始相位和角速度当作顶点属性传进去，位置在顶点着色器里按 ω = K/r^1.5 推进，与行星用同一套开普勒定律，计算全在 GPU 上做，CPU 没有额外开销。

土星环是一个环形网格，u 坐标沿半径方向映射 ring_alpha 贴图，渲染时用 SRC_ALPHA 混合并双面绘制，环境光给得比较多，避免环侧对光源时整圈全黑。行星的昼夜晨昏线没有专门实现，它就是 Phong 漫反射项算出来的自然结果，地月特写截图里地球背阳的那一面可以看到。

### 7. 选做 E1，完整太阳系

做全了 8 颗行星，外加土星环，以及火星和木星轨道之间的小行星带，共 1500 颗；每颗行星的轨道角速度按开普勒第三定律 ω = K/d^1.5 配速，金星逆行自转、天王星躺着转这些特点也按真实数据配了倾角，参数全部集中在 js/config.js 里。

### 8. 选做 E2，日食和月食的模拟，按 1/2/3 切换视角

三种视角都由 camera.js 里的 eclipseView 状态控制，机位每一帧根据地球和月球的实时世界坐标重新计算，坐标直接从层级模型矩阵的第 4 列读出来：

- 日食视角按 2，机位放在地月之间的日地连线上，距地心 3，在月地距离 5.5 的内侧，朝太阳方向看；当月球运行到日地之间也就是朔的时候，它从相机前方 2.5 处掠过日面，看过去的张角是 12.5 度，太阳是 13.9 度，所以会呈现接近全食的金环日食；月球背面被照亮的部分趋于零，整块是黑色剪影，挡住太阳这件事由深度测试自然完成。凌日的瞬间会自动放慢到 0.35 倍，判断依据是对齐度 window.__solarAlign 超过 0.87。从光影上解释，真实日食里月地距离刚好让两个圆盘看起来差不多大，所以才有全食和环食的区别，本场景从地月内侧看月球，张角被放大到接近太阳，于是得到金环效果。
- 月食视角按 3，机位贴着月球、朝地球背日方向看，画面里能看到从地球延伸出来的半透明地影锥，由 geometry.js 的 createUmbraConeData 生成，长度取 3 倍月地距离；月球走进地影时，片元着色器按 uniform uEclipse 把月面颜色往暗红色混。血月的成因在于，本影里直射的阳光被地球挡住，只有穿过地球大气时被散射滤剩的红光能折射到月面上，所以食甚时月亮是暗红色而不是彻底消失。
- 这套模拟在几何上是讲究的：月球轨道面倾斜 5.14 度，就是必做 2 的手动矩阵，满月时月和反日方向的夹角在 0 到 5.14 度之间摆动；ECLIPSE.lunarFadeStart 和 lunarFadeFull 两个参数用夹角的余弦来划食分，夹角小于 4.6 度开始泛红，多数满月都能看到一点，小于 1.5 度达到食甚，大约五分之一的满月能到这一步，对应真实世界月全食只发生在白道交点附近、大概半年一次的规律。再配合前面说的升交点西退，满月相位会周期性扫过交点，形成食季，不会被地球和月球的周期共振锁死。专用视角下时间自动快进 6 倍，减少等待对齐的时间，检测到入影又自动放慢，不然月球 15 秒绕一圈，血月一眨眼就过去了；控制台里随时可以读 window.__lastEclipse 看当前食分。

### 9. 选做 E3，虚拟轨迹球，V 键开关，思路来自 Shoemake 1985

打开之后鼠标拖拽不再走方位角和仰角那套欧拉角，改成经典的虚拟轨迹球，实现代码在 js/camera.js 底部的几个工具函数里，分三步：

1. 先把屏幕像素坐标归一到 -1 到 1 的范围，再映射到一个虚拟的单位球面上，投影在半径 1 以内的点取球面 z = √(1-x²-y²)，落在球外的点放到双曲面 z = 1/r 上，这样在边缘拖拽也是平滑的，不会突变；
2. 拖拽前后两个点在球面上对应一段弧，这段弧就是一个绕轴旋转，用 quatFromTo(p1, p2) 算成四元数，旋转轴取两个向量的叉积，转角的正弦余弦由点积得到；
3. 每次拖拽产生的增量四元数在相机坐标系下从左边乘进累计值 tbQuat，每一帧再用 quatToMat4 转成旋转矩阵，乘在视图矩阵左侧，即 V' = R · V。

选四元数而不是欧拉角，是因为任意方向拖拽的手感一致，而且不会有万向节死锁的问题，原来的 theta、phi 轨道在仰角接近 90 度时方位角会失效；按 V 或 R 会把累计旋转复位成单位四元数。

## 七、已知说明

- 漫游相机的目标点固定在太阳上，拖拽接管之后相机绕原点做球面旋转，滚轮缩放的范围是 12 到 900；
- 正交投影的近远平面按当前相机距离动态计算，不管缩放到多少都不会把场景裁掉；
- 纹理是异步加载的，第一帧之前如果还没加载完，会先用 1×1 的灰色占位，加载完成后自动替换并补生成 mipmap；
- 日食和月食视角下公转时钟自动快进 6 倍，由 ECLIPSE.timeWarp 控制，出现凌日或入影时又自动放慢到 0.35 倍，由 ECLIPSE.eclipseSlowMo 控制，退出视角就恢复正常；月食视角下滚轮调的是远近系数，范围 0.35 到 3.0，不会退出机位；
- 日食呈现接近全食的金环效果，从地月内侧的机位看，月盘张角 12.5 度、日盘 13.9 度；血月的深浅由 ECLIPSE.lunarFadeStart 和 lunarFadeFull 两个余弦阈值控制，半影泛红比较常见，夹角小于 4.6 度就有，食甚的血红色只有大约五分之一的满月能出现，夹角要小于 1.5 度，也就是白道交点附近对齐才行。
